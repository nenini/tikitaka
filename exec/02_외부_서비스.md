# 2. 외부 서비스 정보

프로젝트가 쓰는 외부 서비스와, 새 환경에서 처음부터 붙이는 데 필요한 절차다.

| 서비스 | 용도 | 없으면 |
|---|---|---|
| Google OAuth 2.0 | 소셜 로그인 | 구글 로그인 버튼만 실패. 이메일 가입은 동작 |
| Naver OAuth 2.0 | 소셜 로그인 | **현재 미설정 상태** |
| LiveKit | WebRTC 화상 세션 | **화상 세션 전체 불가** |
| SMTP (Gmail) | 비밀번호 재설정 메일 | 재설정 메일 미발송 |
| Ollama | 챗봇·리포트 생성 LLM | AI 챗봇·리포트 문장 생성 불가 |

> 포톤 클라우드·코드 컴파일 서비스는 **쓰지 않는다.**

---

## 2.1 Google OAuth 2.0

로그인·회원가입의 소셜 인증.

### 발급 절차

1. [Google Cloud Console](https://console.cloud.google.com) 접속 → 프로젝트 생성
2. **API 및 서비스 → OAuth 동의 화면**
   - User Type: `외부`
   - 앱 이름·지원 이메일 입력
   - 범위: `email`, `profile`, `openid`
   - 테스트 사용자에 시연 계정 추가 (게시 전이면 필수)
3. **API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID**
   - 유형: `웹 애플리케이션`
   - **승인된 리디렉션 URI** 를 정확히 등록한다 (하나라도 다르면 `redirect_uri_mismatch`)

| 환경 | 리디렉션 URI |
|---|---|
| 운영 | `https://i15a307.p.ssafy.io/api/v1/auth/oauth2/google/callback` |
| 로컬 | `http://localhost:8080/api/v1/auth/oauth2/google/callback` |

### 환경 변수

```
GOOGLE_OAUTH_CLIENT_ID=<클라이언트 ID>
GOOGLE_OAUTH_CLIENT_SECRET=<클라이언트 보안 비밀>   # GOCSPX- 로 시작
GOOGLE_OAUTH_REDIRECT_URI=<위 표의 값>
```

### 주의

- 백엔드가 콜백을 받아 **토큰을 URL 프래그먼트에 실어** 프런트(`/oauth/callback`)로 302 시킨다.
  그래서 `FRONTEND_BASE_URL` 도 맞아야 한다.
- **소셜 가입 계정은 비밀번호가 없다.** 회원 탈퇴(본인 확인에 비밀번호 필요)와
  비밀번호 재설정이 동작하지 않는다 — 알려진 제약이다.

## 2.2 Naver OAuth 2.0

코드와 환경 변수 자리는 있으나 **현재 앱을 등록하지 않았다.** 구글만 동작한다.

붙이려면 [네이버 개발자센터](https://developers.naver.com) → 애플리케이션 등록 후
아래를 채운다.

```
NAVER_OAUTH_CLIENT_ID=
NAVER_OAUTH_CLIENT_SECRET=
NAVER_OAUTH_REDIRECT_URI=https://i15a307.p.ssafy.io/api/v1/auth/oauth2/naver/callback
```

## 2.3 LiveKit (WebRTC)

화상 세션의 미디어 서버. **이게 없으면 서비스의 핵심 기능이 아예 안 된다.**

### 준비

[LiveKit Cloud](https://cloud.livekit.io) 가입 후 프로젝트를 만들면 아래 세 값이 나온다.
(자체 호스팅도 가능하다 — `LIVEKIT_URL` 만 자체 서버로 바꾸면 된다.)

```
LIVEKIT_URL=wss://<프로젝트>.livekit.cloud
LIVEKIT_API_KEY=<API Key>
LIVEKIT_API_SECRET=<API Secret>
```

LiveKit 프로젝트의 **Webhooks** 설정에 아래 주소와 이벤트를 등록한다.

```text
URL: https://i15a307.p.ssafy.io/internal/livekit/webhook
Events: participant_joined, participant_left
```

웹훅 요청의 `Authorization` 서명은 백엔드가 같은 `LIVEKIT_API_KEY`·
`LIVEKIT_API_SECRET`으로 검증한다.

### 동작 방식

- 브라우저가 직접 LiveKit 에 붙는다. **토큰은 백엔드가 발급**한다
  (`POST /api/v1/sessions/{id}/join` 응답에 실려 온다).
- 방 이름은 `date-room-{matchPairId}` 규칙이다.
- 참가자 상한 `LIVEKIT_MAX_PARTICIPANTS` 기본값이 **3** 인 이유는
  사용자 2명 + **AI 분석 워커 1명**이 들어오기 때문이다. 2로 줄이면 분석이 막힌다.

### 주의

- **HTTPS 가 아니면 브라우저가 카메라·마이크를 안 준다.** 로컬은 `localhost` 예외로 동작한다.
- 세션 시작 조건에 "2명 모두 LiveKit CONNECTED" 가 있고, 이 상태는 **LiveKit webhook**
  으로 서버에 전달된다. 웹훅 경로가 막히면 세션이 영영 시작되지 않는다.

## 2.4 SMTP (Gmail)

비밀번호 재설정 링크 발송에만 쓴다.

### 준비

1. Google 계정 **2단계 인증** 활성화
2. [앱 비밀번호](https://myaccount.google.com/apppasswords) 생성 (16자리)
3. 계정 비밀번호가 아니라 **앱 비밀번호**를 넣는다

```
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=<보내는 계정>
MAIL_PASSWORD=<앱 비밀번호 16자리>
MAIL_FROM=<보내는 주소>
MAIL_SMTP_AUTH=true
MAIL_SMTP_STARTTLS=true
```

### 주의

계정 존재 여부를 흘리지 않으려고 서버는 **없는 이메일에도 202** 를 준다.
"메일이 안 온다" 는 신고가 오면 SMTP 설정과 스팸함을 함께 확인해야 한다.

## 2.5 Ollama (로컬 LLM)

AI 챗봇 응답과 리포트 문장 생성을 맡는다. 외부 API 가 아니라 **서버에 직접 띄우는** LLM 이다.

### 운영 구성

챗봇 컨테이너는 EC2 에서 돌고, **GPU 가 달린 별도 머신의 Ollama 로 역터널**을 통해
호출한다(`.env.prod.example` 주석 참고). EC2 자체에는 GPU 가 없다.

```
챗봇 컨테이너 ──▶ host.docker.internal:18150 ──(역터널)──▶ GPU 서버 Ollama:11434
```

### 환경 변수 — 둘 다 기본값이 있다

| 키 | 기본값 | 언제 바꾸나 |
|---|---|---|
| `OLLAMA_MODEL` | `exaone3.5:7.8b` | GPU 메모리가 부족할 때 |
| `OLLAMA_HOST` | `http://host.docker.internal:18150` | 터널 포트나 배치가 다를 때 |

기본값은 **세 곳에 같은 값으로** 박혀 있다 —
`ai/chatbot/chatbot/api.py:78` · `docker-compose.prod.yml:75` · `.env.prod.example:54`.
따로 지정하지 않아도 뜬다.

### 새 환경에 직접 세울 때

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull exaone3.5:7.8b
ollama serve                                   # 기본 11434
```

컨테이너에서 호스트의 Ollama 를 직접 볼 거라면 포트를 맞춘다.

```
OLLAMA_HOST=http://host.docker.internal:11434
```

### 주의

- **모델을 미리 받아 두지 않으면** 첫 요청이 다운로드를 기다리다 타임아웃된다.
- GPU 여유가 없으면 **경량 모델 `exaone3.5:2.4b`** 로 바꾼다 —
  `ai/docker-compose.yml` 에 주석으로 남겨 뒀다.
- 생성 타임아웃 기본 120초(`OLLAMA_TIMEOUT_SECONDS`).
- **역터널이 끊기면 챗봇·리포트 문장 생성만 멈춘다.** 화상 세션·매칭은 영향이 없다.

## 2.6 내부 서비스 간 인증

외부 가입은 필요 없지만 값을 정해야 한다. 백엔드 ↔ AI 서비스 호출에 쓰는 **공유 토큰**이다.

```
AI_CHAT_INTERNAL_TOKEN=<임의의 긴 랜덤 문자열>
AI_SESSION_INTERNAL_TOKEN=<임의의 긴 랜덤 문자열>
AI_TRANSCRIPT_INTERNAL_TOKEN=<임의의 긴 랜덤 문자열>
```

요청 헤더는 모두 `X-Internal-Token`이다. 대응 관계는 다음과 같다.

| 호출 | 같은 값을 넣을 곳 |
|---|---|
| 백엔드 → chatbot | 백엔드와 chatbot의 `AI_CHAT_INTERNAL_TOKEN` |
| 백엔드 ↔ aggregator | 백엔드와 aggregator의 `AI_SESSION_INTERNAL_TOKEN` |
| 백엔드 → aggregator 전사 조회 | `AI_TRANSCRIPT_INTERNAL_TOKEN`을 비우면 백엔드가 `AI_SESSION_INTERNAL_TOKEN`을 상속한다. 별도로 넣을 때는 aggregator의 `AI_SESSION_INTERNAL_TOKEN`과 같아야 한다 |

nginx는 `/internal/` 요청을 백엔드로 전달만 한다. 실제 검증은 백엔드 컨트롤러와 각 AI
서비스가 수행한다. chatbot은 토큰 미설정 시 개발 편의를 위해 검증을 생략하지만,
aggregator는 토큰이 없으면 500으로 거부하므로 운영에서는 반드시 설정한다.
