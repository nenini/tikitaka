# 4. 시연 시나리오

기준 주소: **https://i15a307.p.ssafy.io**

## 0. 사전 준비

| 항목 | 내용 |
|---|---|
| 계정 | **2개** 필요 (화상 세션은 2인) — 남성 1 · 여성 1 |
| 브라우저 | Chrome 최신. 두 번째 계정은 **시크릿 창** |
| 기기 | 카메라·마이크 권한 허용. **가능하면 서로 다른 PC** (같은 PC 두 창은 오디오 하울링) |
| 시간 | 전체 약 15분 (화상 세션 구간 제외 시 7분) |

> ⚠️ 세션은 **양쪽이 모두 입장·준비·연결**되어야 시작된다. 혼자서는 세션 화면까지 갈 수 없다.
> 시간이 촉박하면 §5 의 단독 시연 경로를 쓴다.

## 1. 첫 진입 — 스플래시 · 로그인 (30초)

| 순서 | 화면 | 동작 | 볼 것 |
|---|---|---|---|
| 1 | `/splash` | 주소 접속 후 **기다린다** | 히어로 영상 위 `START`. **3초 뒤 자동 이동** |
| 2 | | `START` 클릭(기다리지 않으려면) | 하단 진행선이 3초를 시각화 |
| 3 | `/login` | 이메일·비밀번호 입력 → `로그인` | |

**발표자 멘트** — 스플래시는 로고 애니메이션이 아니라 **로그인 상태를 판정하는 시간**이다.
미로그인은 로그인, 온보딩 미완은 온보딩, 완료면 홈으로 갈린다.

## 2. 회원가입 온보딩 (3분)

`/login` 하단 `회원가입` 클릭.

| 순서 | 경로 | 동작 | 볼 것 |
|---|---|---|---|
| 1 | `/signup` | 이메일·비밀번호·생년월일 입력 → `다음` | 이미 가입된 주소면 **이메일 칸에 바로** 오류가 붙는다 |
| 2 | `/signup/verify` | `본인 인증` 클릭 | 데모라 **Mock 즉시 통과** |
| 3 | `/signup/consent` | 필수는 잠금(항상 on), **선택은 꺼진 채 시작** → `동의하고 계속` | 선택 거부해도 진행된다 |
| 4 | `/signup/profile` | 닉네임·성별·시·도 입력 → `다음 · 얼굴 촬영` | `상대 공개` / `매칭 전용` 을 **카드로 갈라** 보여준다 |
| 5 | `/signup/face` | 동의 체크 → `카메라 켜기` → `촬영` | 얼굴상 분석. 실패하면 사유를 알려주고 재촬영 |
| 6 | `/signup/face-result` | 결과 확인 → `다음 · 설문` | 동물 얼굴상 태그 |
| 7 | `/signup/survey` | 성격·원하는 상대·연령·개선 목표 → `시작하기` | → 홈으로 |

**발표자 멘트** — 핵심 세 가지

- **④ 정보 분리** — 상대에게 보이는 것(닉네임·연령대·얼굴상)과 매칭 계산에만 쓰는 것(시·도)을
  화면에서 갈라 놨다. **키·직업·실명·전화·정확한 주소는 아예 수집하지 않는다.**
- **⑤ 선택 동의** — 얼굴 분석에 동의하지 않아도 **화상 세션은 그대로 쓸 수 있다.**
  표정 코칭만 빠진다.
- **③ 거부 기록** — 거부한 항목도 `consented: false` 로 저장한다. "물어본 적 없음" 과 구분된다.

> ① 에 **중복 확인 버튼이 없는 것은 의도**다. 서버에 확인용 API 가 없어서, 예전에는
> 어떤 주소든 "사용 가능" 이라고 해놓고 가입 시점에 `DUPLICATE_EMAIL` 이 나왔다.
> **확인할 수 없는 것을 확인해 준 것처럼 보이는 편이 더 나쁘다** — 지금은 가입 시점의
> 서버 판정 하나만 쓰고, 그 오류를 이메일 칸에 직접 붙인다.

## 3. 매칭 (2분)

**두 계정 모두** 아래를 수행한다.

| 순서 | 경로 | 동작 | 볼 것 |
|---|---|---|---|
| 1 | `/` | 상단 `새 매칭 시작` 클릭 | |
| 2 | `/matching` | 트랙 3개 중 **실사용자 화상 세션** → `매칭 대기 등록` | AI 화상·챗봇은 대기를 유지한 채 쓸 수 있다 |
| 3 | (모달) | 연령 범위·가능 시간대 입력 → 등록 | 초기값은 온보딩 설문에서 끌어온다 |
| 4 | `/matching/queue/:id` | **기다린다** | 맥박형 표시등 · 기다린 시간 |
| 5 | `/matching/pair/current` | 자동 이동 → `수락하기` | 공개 정보가 **닉네임·연령대·얼굴상 셋뿐** |
| 6 | `/session/:id/room` | 양측 수락 시 자동 이동 | |

**발표자 멘트**

- **④ 가짜 진행바를 쓰지 않는다.** 매칭은 줄서기가 아니라 조건이 맞는 상대를 기다리는
  일이라 진척도를 계산할 근거가 없다. **모르는 것을 아는 척하지 않는다.**
- **대기 화면을 벗어나도 대기는 유지된다.** 상단 네비로 홈·챗봇에 다녀와도 된다.
- **⑤ 상대가 거절했는지 시간이 지났는지 구분해 보여주지 않는다** — 거절은 비공개다.

## 4. 화상 세션 (5분)

### 4-1. 대기방 `/session/:id/room`

| 순서 | 동작 | 볼 것 |
|---|---|---|
| 1 | 카메라·마이크 확인 | 미리보기는 **거울처럼 좌우 반전** |
| 2 | **스피커 테스트음 재생** | 강조 표시. 눌러야 준비 완료가 된다 |
| 3 | `준비 완료` | 상대 준비 상태가 실시간으로 보인다 |
| 4 | 양측 준비 → 자동 시작 | |

**발표자 멘트** — 대기방에서 **LiveKit 연결을 미리 붙여 둔다**(프리워밍). 그래서 세션에
들어갈 때 협상·화질 ramp-up 5초가 화면에 보이지 않는다.

### 4-2. 세션 `/session/:id`

| 볼 것 | 위치 | 설명 |
|---|---|---|
| 상대 영상 | 중앙 | 다크 고정 — 상대 얼굴이 주인공 |
| 내 영상 | 우하단 PIP | 좌우 반전 |
| **코칭 오버레이** | 영상 위 중앙 | 웹캠 근처에 둬 **시선이 렌즈를 벗어나지 않게** |
| **코칭 기록** | 우측 레일 | 지나간 코칭이 최신순으로 쌓인다 |
| 미션 | 우측 레일 | 서버가 배정 |
| 타이머 | 상단 | **서버가 SSOT** |

시연 동작

1. **웃어 본다** → 표정 분석이 감지 (`SMILE`)
2. **화면 밖을 오래 본다** → `시선이 오래 벗어났어요` 힌트
3. **둘 다 말을 멈춘다** → 침묵 감지 → 우측 레일에 **질문 카드** 제안
4. 종료 5분 전 → **5분 연장 제안** 카드 (양측 동의 시 연장)
5. `종료` → 확인 모달 → 상호 평가로

**발표자 멘트** — 서비스 핵심

> **표정 분석은 브라우저 안에서 끝난다.** MediaPipe 가 프레임을 읽고 **스칼라 지표만**
> LiveKit DataChannel 로 AI 워커에 보낸다. **원본 영상은 서버로 가지 않는다.**

> **코칭은 본인에게만 보인다.** 우측 레일 상단에 `나에게만 보여요` 를 항상 띄운다.

## 5. 평가 · 리포트 (3분)

| 순서 | 경로 | 동작 | 볼 것 |
|---|---|---|---|
| 1 | `/session/:id/review` | 상대 평가 제출 | |
| 2 | `/session/:id/feedback` | 내가 받은 피드백 | **양쪽이 제출해야 열린다** |
| 3 | `/session/:id/report` | AI 리포트 | 생성 중이면 준비 중 화면 |
| 4 | `/reports` | 홈 → `리포트` | **화상 세션 / AI 챗봇** 두 트랙 |
| 5 | `/growth` | 홈 → `성장` | 사랑의 온도 추이 · 뱃지 |

**발표자 멘트** — 리포트 화법 규칙

- **점수·등수를 만들지 않는다.** 사실과 횟수만 남긴다
- **측정하지 못한 축은 비워 둔다.** 샘플 점수를 채워 넣지 않는다
- 생성 중·실패 상태에서도 **가짜 값을 보여주지 않는다**

**뱃지 착용** — `/growth` 에서 뱃지를 눌러 착용/해제. 착용한 것에 체크 점이 붙는다.

## 6. AI 트랙 (2분)

혼자서도 시연할 수 있는 구간이다.

### 6-1. AI 챗봇 `/chatbot/persona`

| 순서 | 동작 | 볼 것 |
|---|---|---|
| 1 | 홈 → `AI 챗봇` | **진행 중 대화가 있으면 그 대화로 바로** 들어간다 |
| 2 | 연습 단계(소개팅 전/후) 선택 → `대화 시작` | |
| 3 | 메시지 전송 | **SSE 스트리밍**으로 한 글자씩 |
| 4 | `종료` → 종합 피드백 | |

### 6-2. AI 화상 연습 `/ai-video/setup`

| 순서 | 동작 | 볼 것 |
|---|---|---|
| 1 | 홈 → `AI 화상 5분` | |
| 2 | 주제 선택(첫 만남·취미·일·음식·여행) → `연습 시작` | |
| 3 | 질문에 소리 내어 답한다 | 1분마다 다음 질문 |
| 4 | 종료 → 요약 | 웃은 횟수·시간·끄덕임 |

> ⚠️ **AI 화상 연습은 기록되지 않는다.** 영상·표정 분석 모두 브라우저 안에서만
> 처리하고 서버로 보내지 않는다 — 화면에서도 그렇게 안내한다. 리포트·사랑의 온도에
> 반영되지 않는다.

## 8. 시연 중 막혔을 때

| 증상 | 원인 | 대응 |
|---|---|---|
| 세션이 시작되지 않는다 | 한쪽이 `준비 완료` 미클릭 또는 LiveKit 미연결 | 양쪽 대기방에서 준비 상태 확인 |
| 카메라가 안 켜진다 | 권한 거부 / 다른 앱 점유 | 주소창 자물쇠 → 권한 허용 → 새로고침 |
| 표정 코칭이 안 뜬다 | 얼굴 분석 **미동의** 또는 모델 로드 실패 | 정상 동작일 수 있다. 통화 화면 하단 배너 확인 |
| 매칭이 안 잡힌다 | 나이·성별·시간대 조건 불일치, 재매칭 쿨다운 | `조건 완화` 로 범위를 넓힌다 |
| 구글 로그인 실패 | 리디렉션 URI 불일치 | 이메일 계정으로 진행 |
| 챗봇 응답이 느리다 | Ollama 모델 미로딩 | 시연 전에 한 번 대화를 돌려 예열한다 |

**시연 전 예열 권장** — 시연 30분 전에 챗봇 대화 1회, 화상 세션 1회를 미리 돌려
Ollama 모델과 LiveKit 연결을 깨워 둔다.
