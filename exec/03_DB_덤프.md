# 3. DB 덤프

## 3.1 첨부 파일

| 파일 | 내용 |
|---|---|
| [`db/01_schema.sql`](./db/01_schema.sql) | **74개 테이블 전체 스키마** (DDL only) |
| [`db/02_master_data.sql`](./db/02_master_data.sql) | 마스터·기준 데이터 + Flyway 이력 |

- 기준: **MySQL 8.4.11** · 스키마명 `date` · `utf8mb4`
- 스키마 버전: Flyway **V63** (마이그레이션 파일 47개)

### 02_master_data.sql 에 담긴 테이블

`badge_catalog` · `consent_types` · `face_tag_catalog` · `matching_policies` ·
`mission_catalog` · `practice_goal_catalog` · `question_cards` · `trait_catalog` ·
`flyway_schema_history`

서비스가 **뜨자마자 필요한 기준 데이터**만 골랐다. 뱃지 정의, 동의 항목, 얼굴상 태그,
매칭 정책, 미션·질문 카드가 여기 들어 있다.

---

## 3.2 ⚠️ 사용자 데이터는 넣지 않았다

`users` · `user_profiles` · `sessions` · `reports` · `chatbot_messages` 등
**개인정보가 담기는 테이블은 덤프에서 제외**했다.

- 실명·이메일·얼굴 분석 결과·대화 내용이 들어 있어 저장소에 올릴 수 없다
- 비밀번호 해시(`users.passwordHash`), 리프레시 토큰(`refresh_tokens`),
  재설정 토큰(`password_reset_tokens`)도 같은 이유로 뺐다

스키마(`01_schema.sql`)에는 **모든 테이블의 구조가 들어 있다.** 데이터만 없다.

## 3.3 복원 방법

### 방법 A — 애플리케이션에 맡긴다 (권장)

**Flyway 가 기동할 때 스키마와 기준 데이터를 자동으로 만든다.**
빈 DB 만 준비하면 덤프 파일이 필요 없다.

```sql
CREATE DATABASE date CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'date'@'%' IDENTIFIED BY '<비밀번호>';
GRANT ALL PRIVILEGES ON date.* TO 'date'@'%';
```

```bash
cd backend && ./gradlew bootRun --args='--spring.profiles.active=local'
```

### 방법 B — 덤프로 직접 복원

DB 만 먼저 세우고 싶을 때 쓴다.

```bash
mysql -h 127.0.0.1 -u date -p date < exec/db/01_schema.sql
mysql -h 127.0.0.1 -u date -p date < exec/db/02_master_data.sql
```

> **순서를 지켜야 한다.** 스키마 → 마스터 데이터.

> ⚠️ 이 방법으로 복원하면 `flyway_schema_history` 까지 함께 들어가므로,
> 애플리케이션이 **마이그레이션을 이미 적용된 것으로 본다.** 덤프와 소스의
> 마이그레이션 버전이 어긋나면 기동 시 Flyway 가 검증에 실패한다.
> 버전이 맞지 않으면 방법 A 를 쓴다.

## 3.4 덤프를 다시 뜨는 방법

스키마가 바뀌면 아래로 갱신한다.

```bash
# 스키마
mysqldump -h 127.0.0.1 -u date -p \
  --no-tablespaces --no-data --single-transaction \
  --set-gtid-purged=OFF --skip-comments \
  date > exec/db/01_schema.sql

# 마스터 데이터
mysqldump -h 127.0.0.1 -u date -p \
  --no-tablespaces --no-create-info --single-transaction \
  --set-gtid-purged=OFF --skip-comments --complete-insert \
  date badge_catalog consent_types face_tag_catalog face_tag_examples \
       matching_policies mission_catalog practice_goal_catalog \
       question_cards room_themes trait_catalog flyway_schema_history \
  > exec/db/02_master_data.sql
```

옵션 이유

| 옵션 | 왜 |
|---|---|
| `--no-tablespaces` | 일반 계정에 `PROCESS` 권한이 없어 이게 없으면 실패한다 |
| `--set-gtid-purged=OFF` | 복제 설정이 덤프에 섞이지 않게 |
| `--complete-insert` | 컬럼명을 명시해 스키마가 조금 바뀌어도 복원이 깨지지 않게 |
| `--skip-comments` | 덤프 시각 주석이 매번 바뀌어 **의미 없는 diff** 가 생기는 것을 막는다 |

**덤프를 다시 뜬 뒤에는 개인정보가 섞이지 않았는지 확인한다.**

```bash
grep -ci "@gmail\|@naver\|@example.com" exec/db/02_master_data.sql   # 0 이어야 한다
```

## 3.5 스키마 개요

74개 테이블을 도메인별로 묶으면 이렇다.

| 도메인 | 주요 테이블 |
|---|---|
| 계정·인증 | `users` · `user_profiles` · `oauth_accounts` · `refresh_tokens` · `password_reset_tokens` |
| 동의 | `consent_types` · `user_consents` |
| 얼굴상 | `face_analysis_requests` · `face_analysis_results` · `face_tag_catalog` · `user_face_tags` |
| 설문·선호 | `trait_catalog` · `user_traits` · `user_preferred_*` · `user_availability_slots` |
| 매칭 | `match_requests` · `active_match_requests` · `match_pairs` · `match_responses` · `match_jobs` · `matching_policies` |
| 세션 | `sessions` · `session_participants` · `room_themes` · `room_device_checks` · `livekit_webhook_events` |
| 실시간 코칭 | `coaching_events` · `ai_coaching_events` · `silence_events` · `question_cards` · `safety_events` |
| 미션 | `mission_catalog` · `session_missions` · `session_goals` |
| 평가·리포트 | `peer_evaluations` · `reports` · `session_reports` · `report_evidences` · `session_metric_summaries` |
| 성장 | `user_temperatures` · `love_temperature_histories` · `growth_metric_snapshots` · `badge_catalog` · `user_badges` |
| 챗봇 | `chatbot_conversations` · `chatbot_messages` · `chatbot_personas` |
| 안전·제재 | `user_blocks` · `sanctions` · `attendance_penalties` |
| 알림 | `notifications` · `notification_jobs` |

`_legacy` 접미사 테이블(`peer_evaluations_legacy` · `safety_events_legacy`)은
마이그레이션 과정에서 남은 것으로 **현재 코드가 쓰지 않는다.**
