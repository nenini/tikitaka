BACKEND · AI_CHAT-03

SSE 코드, 실행 순서대로 읽기

Frontend 요청이 들어온 순간부터 사용자 메시지 저장, 비동기 AI 작업, chunk 전송, 완료·오류 처리와 자원 정리까지 실제 코드의 책임을 하나씩 설명합니다.

전체 테스트 98개 통과
전체 흐름 Controller Stream Service 비동기 실행기 AI 연동 경계 SSE 이벤트 자원 정리 테스트

전체 흐름

HTTP 요청
USER 메시지 저장
SSE 즉시 반환
AI 비동기 실행
chunk 순차 전송
AI 저장·종료
AI_CHAT_BASE_URL을 설정하면 실제 HTTP 스트리밍 구현이 활성화됩니다. 설정하지 않은 환경에서는 명확한 error 이벤트를 반환하는 기본 구현을 사용합니다.

1. 요청 진입 — AiChatStreamController

1

AiChatStreamController.java

JWT에서 인증 사용자 ID를 받고 URL의 세션 ID, 본문의 사용자 메시지를 서비스로 전달합니다.

@PostMapping(
    value = "/stream",
    produces = MediaType.TEXT_EVENT_STREAM_VALUE
)
public SseEmitter stream(
    @AuthenticationPrincipal AuthUser authUser,
    @PathVariable Long sessionId,
    @Valid @RequestBody AiChatStreamRequest request
) {
    return streamService.stream(
        authUser.userId(),
        sessionId,
        request.messageText()
    );
}

text/event-stream은 일반 JSON 한 번이 아니라 여러 SSE 이벤트가 같은 HTTP 연결을 통해 전달된다는 뜻입니다.

2

AiChatStreamRequest.java

사용자가 보낸 메시지가 비어 있지 않은지, 5,000자를 넘지 않는지 검증합니다.

public record AiChatStreamRequest(
    @NotBlank
    @Size(max = 5000)
    String messageText
) {}

2. SSE 연결 생성 — AiChatStreamService

3

사용자 메시지 먼저 저장

AiChatMessageResponse userMessage =
    messageService.saveUserMessage(
        userId,
        sessionId,
        userMessageText
    );

이 과정에서 세션 존재 여부와 소유자가 검증됩니다. 검증에 실패하면 SSE 연결을 만들기 전에 일반 HTTP 403 또는 404 응답이 반환됩니다.

4

SseEmitter와 스트림 ID 생성

SseEmitter emitter = new SseEmitter(60_000L);
String streamId = UUID.randomUUID().toString();
ActiveStream activeStream = new ActiveStream(emitter);
activeStreams.put(streamId, activeStream);

SseEmitter가 열린 HTTP 연결을 나타냅니다. 제한 시간은 60초이며, UUID를 이용해 현재 처리 중인 스트림을 추적합니다.

5

콜백 등록

emitter.onCompletion(() -> removeStream(streamId));
emitter.onTimeout(() -> cancelStream(streamId));
emitter.onError(error -> cancelStream(streamId));

정상 종료, 타임아웃, 네트워크 오류 중 어떤 경우에도 활성 스트림이 메모리에 남지 않게 합니다.

3. 비동기 처리 — 요청 스레드와 AI 스레드 분리

HTTP 요청 스레드

사용자 메시지를 저장하고 AI 작업을 제출한 다음 SseEmitter를 바로 반환합니다.

ai-chat-stream-* 스레드

AI 응답을 받고 chunk를 전송하며 완성된 답변을 DB에 저장합니다.

FutureTask<Void> task = new FutureTask<>(() -> {
    processStream(...);
    return null;
});

activeStream.setFuture(task);
streamExecutor.execute(task);
return emitter;

4. AI 서버 연결 경계

6

AiChatResponseStreamer.java

public interface AiChatResponseStreamer {
    void stream(
        AiChatResponseStreamRequest request,
        Consumer<String> chunkConsumer
    ) throws Exception;
}

실제 HTTP 구현은 AI 서버에 POST 요청하고 SSE·NDJSON·일반 텍스트 스트림을 읽은 뒤, 답변 조각마다 chunkConsumer.accept(chunk)를 호출합니다.

7

HttpAiChatResponseStreamer.java

AI_CHAT_BASE_URL이 있으면 실제 구현을 사용하고, 값이 없으면 UnconfiguredAiChatResponseStreamer가 설정 누락을 error 이벤트로 알립니다.

5. 이벤트를 순서대로 전송

connected

SSE 연결과 사용자 메시지 저장 완료를 알립니다.

{"sessionId":1,"userMessageId":10}

chunk

AI 답변 조각과 스트림 내부 순번을 전달합니다.

{"sequence":1,"content":"안녕"}

done

완성된 AI 답변의 DB 저장까지 끝났음을 알립니다.

{"sessionId":1,"aiMessageId":11,"messageSequence":2}

error

연결 후 발생한 AI 처리 실패를 SSE 이벤트로 알립니다.

{"code":"AI_RESPONSE_STREAM_FAILED",
 "message":"AI 응답을 전송하지 못했습니다."}
long sequence = chunkSequence.incrementAndGet();
completeResponse.append(chunk);
send(activeStream, "chunk",
    new AiChatStreamChunkEvent(sequence, chunk));

한 작업 스레드에서 AI가 전달한 순서대로 번호를 증가시키고 바로 전송하므로 Frontend는 sequence를 기준으로 순서를 확인할 수 있습니다.

6. 완료 저장과 자원 정리

8

AI 답변 합치기 및 DB 저장

AiChatMessageResponse aiMessage =
    messageService.saveAiMessage(
        userId,
        sessionId,
        completeResponse.toString()
    );

send(activeStream, "done", ...);
activeStream.emitter().complete();

chunk를 각각 DB에 넣지 않고 완성된 답변 하나를 AI 메시지로 저장합니다.

9

모든 종료 경로에서 정리

finally {
    removeStream(streamId);
}

정상 완료와 예외 모두 finally를 지나므로 활성 스트림 Map에서 제거됩니다. 연결이 먼저 종료되면 저장된 Future를 취소해 AI 작업도 중단합니다.

Swagger UI는 일반 JSON 응답 확인에는 편리하지만 SSE 스트림 관찰에는 제한이 있습니다. 실제 연결 확인은 curl -N 또는 Frontend의 fetch 스트림 처리를 사용하는 편이 정확합니다.
