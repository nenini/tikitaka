## 1. 제작 규칙

### 1.1 프레임 명명

```text
WF-{화면군}-{번호}/{viewport}/{state}

예:
WF-H-01/D/NoSession
WF-H-01/M/UpcomingSession
WF-S-02/M/Reconnecting
```

Viewport 코드는 다음과 같다.

| 코드 | 기준 폭 | 용도 |
|---|---:|---|
| `M` | 390px | 기본 모바일 |
| `M320` | 320px | 최소 폭 예외 검수 |
| `T` | 840px | 주요 레이아웃 전환 검수 |
| `D` | 1440px | 기본 데스크톱 |

모든 기본 보드는 `M`과 `D`를 만든다. `T`는 내비게이션, 히어로, 2열 폼, 미디어 화면처럼 구조가
바뀌는 화면만 만든다. `M320`은 텍스트/버튼 충돌 가능성이 높은 화면만 별도 보드를 만든다.

### 1.2 보드에 반드시 적을 주석

- 라우트와 진입 조건
- 실제 데이터 필드와 가변 길이
- Primary/Secondary/Danger 행동과 이동 경로
- 로딩, 빈 상태, 오류, 권한, 오프라인 처리
- 고정/스크롤 영역과 safe-area
- breakpoint별 숨김/이동/재배치 규칙
- 포커스 순서와 최소 44×44px 터치 영역
- 미디어 비율, crop safe area, poster/실패 폴백

### WF-H-01 히어로 배치 주석

- D: 영상 16:10 cover. 왼쪽 역광 인물은 보존하고 카피는 오른쪽 바다·하늘의 여백에 둔다.
- T: copy와 피사체가 겹치면 copy를 하단으로 내린다.
- M: 세로형 영상 확보 전 4:3 영상 상단 + Paper CTA 시트를 기본안으로 한다.
- poster는 영상에서 추출한 동일 장면을 사용한다.
- 대표 장면뿐 아니라 0초, 5초, 10초, 14초 프레임을 겹쳐 전체 동선의 crop 안전영역을 검수한다.
- 동적 CTA 세 상태의 버튼 폭과 문장 길이를 모두 검수한다.

| 오버레이 | 4 | 전역 재사용 |
| 내부/후속 | 2 | Gallery 우선 |
| **합계** | **47** | 각 기본 보드는 원칙적으로 M/D 한 쌍 |

47개는 라우트 수가 아니라 **재사용 가능한 화면 패턴 보드 수**다. 동일 레이아웃의 가입/수정 화면은
한 보드의 mode 변형으로 관리한다. 상태와 viewport를 펼치면 실제 프레임 수는 약 110~140개가 예상된다.

## 15. 와이어프레임 승인 체크리스트

- 실제 라우트와 진입/이탈 경로가 표시되어 있는가?
- 한 화면의 Primary CTA가 하나인가?
- 가변 데이터가 길어져도 레이아웃이 유지되는가?
- 정상 상태 외 Loading/Empty/Error/Offline이 정의됐는가?
