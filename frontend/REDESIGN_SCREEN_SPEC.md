## 1. 확정 전제

- 사용자 노출 서비스명은 **티키타카**다.
- 현재 `tika-logo-black.png`, `tika-logo-whitever.webp` 로고 형태를 그대로 사용한다.
- `/reports`, `/growth`를 개편 범위에 포함한다.
- `/admin/*`, `/gallery`, `/demo`, `/livekit-demo`는 사용자 화면 완료 후 별도 처리한다.
- 메인 페이지 히어로는 `public/main_hero_video.mp4`를 사용한다.
- 메인 영상은 15초, 720×540, 4:3, 24fps, 약 0.9MB다.
- 전역 기본 배경과 카드는 White `#FFFFFF`, 주요 CTA와 선택 강조는 Klarna Pink `#FFB3C7`, 라벨은 Ink `#17120F`, 링크와 다크 표면은 Chocolate `#5A382C`/`#2F1D17`을 사용한다.

## 2. 공통 화면 계약

### 2.1 셸 유형

| 코드 | 셸 | 적용 화면 |
|---|---|---|
| `S-APP` | 제품 AppShell | 홈, 매칭 진입, 리포트, 성장, 마이 |
| `S-AUTH` | 인증/온보딩 셸 | 로그인, 가입, 본인 인증, 동의, 프로필, 설문 |
| `S-FOCUS` | 과업 집중 셸 | 매칭 대기/수락, 계정 수정, 평가 |
| `S-MEDIA` | 다크 미디어 셸 | 얼굴 촬영, 대기방, 화상 세션 |
| `S-CHAT` | 대화 셸 | 챗봇 설정, 대화, 챗봇 리포트 |
| `S-REPORT` | 편집형 결과 셸 | 세션 리포트, 성장 대시보드 |

### 2.2 공통 헤더

- 로고는 이미지 자산을 사용하며 텍스트로 다시 그리지 않는다.
- 데스크톱 AppShell은 중앙 캡슐 내비게이션, 우측 알림과 프로필을 사용한다.
- 모바일 AppShell은 하단 내비게이션을 기본으로 하고, 히어로 위에는 로고와 메뉴/알림만 둔다.
- 집중 셸은 뒤로가기, 화면 제목, 필요한 보조 행동 하나만 둔다.
- 세션 셸은 전역 내비게이션을 숨기고 연결 상태, 타이머, 종료만 유지한다.

### 2.3 공통 상태

모든 API 화면은 아래 상태를 별도 화면 또는 컴포넌트 변형으로 명세한다.

1. 최초 진입
2. 로딩
3. 정상 데이터
4. 빈 데이터
5. 부분 데이터
6. 복구 가능한 오류
7. 권한/자격 부족
8. 오프라인 또는 실시간 연결 끊김
9. 제출 중과 중복 제출 방지
10. 완료 후 다음 행동

### 2.4 CTA 위계

- Primary: 화면의 다음 단계 하나
- Secondary: 이전, 나중에, 설정 변경
- Tertiary/Text: 상세 보기, 도움말
- Danger: 세션 종료, 신고, 탈퇴처럼 회복 비용이 큰 행동
- 같은 화면에 Primary fill 버튼을 두 개 이상 두지 않는다.

## 3. 메인 페이지 상세 명세

### H-01 홈 `/`

**목적**  
브랜드 인상을 전달하면서 로그인 사용자가 지금 해야 할 한 가지 행동을 바로 선택하게 한다.

**히어로 미디어**

- 소스: `public/main_hero_video.mp4`
- 속성: `autoplay muted loop playsinline preload="metadata"`
- 대표 장면 기준으로 어두운 역광 인물이 왼쪽에 있고, 바다와 하늘의 네거티브 스페이스가 오른쪽에 열린
  구도다. 카피는 인물 중앙을 덮지 않고 오른쪽 7~11열을 우선 사용한다.
- 영상과 동일 장면에서 `main_hero_poster.webp`를 추출해 poster로 사용한다.
- `prefers-reduced-motion: reduce`에서는 자동 재생하지 않고 poster만 표시한다.
- 로딩/재생 실패 순서는 poster → Forest 단색 배경이다.
- 영상은 정보 전달 요소가 아닌 분위기 요소이므로 `aria-hidden="true"`로 처리한다.

**데스크톱 구조**

1. 20~24px top safe area의 inverse 캡슐 내비게이션
2. 16:10 히어로 프레임, 최소 높이 `calc(100svh - 32px)`
3. 영상 전체 스크림 12~18% + 하단 그라디언트 40~50%
4. 오른쪽 네거티브 스페이스의 2~3줄 흰색 헤드라인
5. 하단 상태 요약 문장 + 동적 Primary CTA
6. 다음 섹션을 암시하는 짧은 스크롤 라벨

720×540 영상을 16:10으로 채우면 상하 약 45px씩 잘릴 수 있다. 초기 대표 장면에서는 왼쪽 인물과 오른쪽
카피 영역을 함께 보존할 수 있지만, 전체 15초 동안 인물 동선이 같은 안전영역에 남는지 확인한 뒤
`object-position`을 확정한다. 1440px 이상에서는 업스케일이 눈에 띌 수 있어 동일 편집의 1920×1080 이상
재출력을 권장한다.

**모바일 구조**

현재 4:3 원본을 4:5 full-bleed로 강제하면 좌우 약 40%가 잘리고 왼쪽 인물 또는 오른쪽 카피 영역 중
하나가 사라질 수 있다. 세로형 원본 확보 전에는:

1. 상단 52~58svh에 4:3 영상 프레임을 유지한다.
2. 하단 Paper 시트에 헤드라인, 상태 문장, CTA를 둔다.
3. 영상 위에는 로고와 음소거 상태 표시만 둔다.
4. 세로형 원본 확보 후 4:5 full-bleed 변형으로 교체할 수 있게 컴포넌트를 구성한다.

**콘텐츠 우선순위**

- 초안 헤드라인: `오늘도 한 걸음, 대화를 연습해볼까요?`
- 예정 세션 있음: 시간/상대 별칭 → `대기방 입장`
- 수락 대기: 매칭 상태 → `매칭 확인`
- 예정 세션 없음: 짧은 가치 문장 → `새 매칭 시작`
- Secondary: `AI 챗봇으로 연습하기`

**히어로 아래**

1. 최근 세션에서 얻은 성장 포인트 한 문장
2. 사랑의 온도와 누적 기록을 한 개의 `MetricStory`로 통합
3. 최근 완성 리포트 최대 2개
4. 모든 기록이 없을 때 시작 행동을 반복하는 Final CTA

**상태**

- 사용자/매칭/리포트 병렬 로딩
- 예정 세션 있음, 수락 대기, 없음
- 리포트 있음, 생성 중만 있음, 없음
- 히어로 영상 로딩 실패, reduced-motion
- 알림 있음/없음

## 4. 인증과 온보딩

### A-01 스플래시 `/splash`

- 목적: 인증·온보딩 상태를 판정하는 짧은 전환 화면
- 구조: Paper 또는 Ink 단색 배경, 기존 로고, 1줄 상태 라벨
- 행동: 자동 이동만 제공하되 5초 이상 지연 시 `다시 시도` 표시
- 금지: 스킵할 수 없는 긴 로고 애니메이션
- 상태: 판정 중, 네트워크 오류, 온보딩 재개, 로그인/홈 이동

### A-02 로그인 `/login`

- 목적: 이메일 또는 소셜 계정으로 진입
- 데스크톱: 좌측 7열 브랜드 미디어, 우측 5열 로그인 폼
- 모바일: 상단 이미지/영상 poster + 하단 Paper 폼 시트
- 순서: 로고 → 환영 문장 → 이메일/비밀번호 → 로그인 → 소셜 → 가입 링크
- Primary: `로그인`
- 상태: 필드 오류, 인증 실패, 제출 중, OAuth 이동 실패
- 키보드가 열린 모바일에서도 로그인 버튼과 오류가 보이도록 폼을 스크롤 영역으로 둔다.

### A-03 계정 생성 `/signup`

- 목적: 계정 생성에 필요한 정보 수집
- 구조: 진행률 → 계정 정보 → 본인 정보 → 약관 링크 → CTA
- 이메일, 비밀번호, 비밀번호 확인, 실명, 전화번호, 생년월일을 논리 그룹으로 나눈다.
- 비밀번호 강도는 색과 텍스트를 함께 사용한다.
- Primary: `계정 만들기`
- 상태: 이메일 중복, 비밀번호 불일치, 서버 검증 오류, 제출 중

### A-04 본인 인증 `/signup/verify`

- 목적: 성인 여부와 본인 확인
- 구조: 이유 설명 → 인증 수단 선택 → 개인정보 고지 → 인증 CTA
- 외부 인증으로 이동하기 전 돌아왔을 때 이어진다는 점을 알려준다.
- 상태: 인증 중, 성공, 취소, 만료, 실패, 이미 인증됨

### A-05 목적별 동의 `/signup/consent`

- 목적: 필수/선택 동의를 목적별로 이해하고 선택
- 구조: 전체 동의는 보조 도구, 각 목적이 주 정보
- 필수/선택 라벨을 텍스트로 명시하고 상세 약관은 별도 시트로 연다.
- Primary: 필수 항목 충족 시 `동의하고 계속`
- 상태: 목록 로딩, 저장 실패, 선택 동의 거부

### A-06 기본 프로필 `/signup/profile`

- 목적: 매칭에 필요한 최소 공개 프로필 설정
- 구조: 공개 범위 안내 → 닉네임 → 성별 → 지역 → CTA
- 닉네임 중복/형식 검증은 필드 가까이 표시한다.
- 정확한 위치가 아니라 시·도만 받는 이유를 설명한다.
- 상태: 기존 데이터 복원, 검증 중, 저장 실패

### A-07 얼굴 촬영 `/signup/face`, `/me/edit/face`

- 목적: 얼굴상 분석용 이미지 촬영 또는 재촬영
- `S-MEDIA` 다크 셸을 사용한다.
- 순서: 권한 전 설명 → 카메라 프리뷰 → 가이드 오벌/조명 안내 → 촬영 → 확인
- Primary: 촬영 전 `카메라 허용`, 촬영 후 `이 사진 사용`
- Secondary: `다시 찍기`
- 상태: 권한 거부, 카메라 없음, 촬영 중, 분석 전송 중, 서비스 연결 실패
- 재촬영 모드에서는 기존 결과가 언제 교체되는지 명시한다.

### A-08 얼굴상 결과 `/signup/face-result`, `/me/edit/face-result`

- 목적: 분석 결과를 가볍고 비평가적으로 설명
- 구조: 동물 이미지 → 결과명 → 특징 2~3개 → 참고용 고지 → CTA
- 외모 점수, 순위, 우열 표현을 금지한다.
- Primary: 온보딩 `다음으로`, 수정 모드 `결과 저장`
- 상태: 결과 없음, 분석 중, 분석 실패, 재촬영

### A-09 선호/목표 설문 `/signup/survey`, `/me/edit/survey`

- 목적: 선호 조건과 연습 목표 설정
- 한 화면에 모든 카드를 쌓지 않고 4단계 질문 흐름으로 나눈다.
- 단계: 선호 얼굴상 → 상대 성격/나의 성격 → 연령 → 개선 목표
- Primary: 단계별 `다음`, 마지막 `설문 저장`
- 선택 수 제한과 이유를 즉시 표시한다.
- 상태: 옵션 로딩, 기존 응답 복원, 저장 실패, 미완료 이탈

### A-10 비밀번호 재설정 `/forgot-password`

- 목적: 이메일 확인 후 재설정 경로 안내
- 구조: 이메일 입력 → 발송 완료 상태 → 재발송/로그인 복귀
- 계정 존재 여부를 노출하지 않는 문장을 사용한다.
- 상태: 입력, 발송 중, 발송 완료, 횟수 제한, 실패

### A-11 OAuth 콜백 `/oauth/callback`

- 목적: 토큰 처리와 다음 경로 판정
- 사용자에게 기술 메시지 대신 `로그인을 마무리하고 있어요`를 보여준다.
- 상태: 처리 중, 온보딩 필요, 완료, 토큰 누락/만료, 재시도

## 5. 매칭

### M-01 트랙 선택 `/matching`

- 목적: 실사용자 화상, AI 화상, AI 챗봇 중 가능한 연습 방식 선택
- 출시되지 않은 트랙은 동일한 활성 카드로 보이지 않게 한다.
- 각 카드: 장면 이미지/그래픽 → 누구와 → 방식/시간 → 기대 결과 → 행동
- Primary는 현재 선택한 트랙의 시작 행동 하나다.
- 실사용자 카드가 기본 추천이며 `매칭 조건 설정` 시트를 연다.
- 상태: 온보딩 미완료, 진행 중 매칭 있음, 이용 불가 트랙, API 오류

### M-02 매칭 조건 시트

- 경로 없이 M-01에서 열리는 modal/sheet 패턴
- 연령 범위, 가능 시간대, 얼굴상 선호를 설정한다.
- 현재 설정 요약과 예상 대기시간은 서버 근거가 있을 때만 표시한다.
- Primary: `이 조건으로 찾기`
- 상태: 기본값, 기존 큐 수정, 유효성 오류, 제출 중

### M-03 매칭 대기 `/matching/queue/:requestId`

- 목적: 대기 진행 상황을 안정적으로 안내하고 조건 변경/취소 제공
- 구조: 상태 애니메이션 → 제목 → 경과/예상 정보 → 현재 조건 → 보조 행동
- Primary는 없다. 대기는 시스템이 수행하므로 조건 변경과 취소는 Secondary/Text로 둔다.
- 상태: 검색 중, 조건 완화 제안, 매칭 발견, 만료, 취소, 연결 끊김, 잘못된 requestId
- reduced-motion에서 beacon은 정적 상태 아이콘으로 바뀐다.

### M-04 매칭 카드 `/matching/pair/:pairId`

- 목적: 공개 가능한 상대 정보와 세션 조건을 확인하고 수락 결정
- 구조: 상대 아바타/별칭 → 공개 프로필 → 일정/테마/내 목표 → 양측 수락 상태 → 정책
- Primary: `매칭 수락`
- Secondary/Danger: `거절` 또는 수락 후 `일정 취소`
- 카운트다운이 있으면 숫자와 종료 시각을 함께 제공한다.
- 상태: 응답 전, 나만 수락, 상대만 수락, 확정, 거절, 만료, 취소

## 6. 대기방과 세션

### S-01 대기방 `/session/:sessionId/room`

- 목적: 기기와 환경을 확인하고 양측 준비 상태를 맞춤
- `S-MEDIA` 셸, 카메라 프리뷰를 가장 큰 영역으로 사용한다.
- 데스크톱: 미디어 8열 + 점검/상태 4열
- 모바일: 미디어 상단 + 점검 카드 하단 시트
- 점검: 카메라, 마이크, 네트워크, 환경음/분석 동의
- Primary: 모든 필수 점검 통과 후 `준비 완료`
- 상태: 기기 검색, 권한 거부, 일부 실패, 나 준비, 상대 대기, 양측 준비, 입장 카운트다운

### S-02 화상 세션 `/session/:sessionId`

- 목적: 상대 영상에 집중하면서 최소한의 통화 제어와 개인 코칭 제공
- 구조: 상대 영상 주 화면, 내 영상 PIP, 상단 타이머/연결, 하단 통화 컨트롤
- 코치 레일은 데스크톱 측면, 모바일 하단 오버레이로 표시한다.
- 마이크/카메라 끔은 중립색, 종료만 danger를 사용한다.
- 신고는 종료와 분리하고 확인/사유 시트를 거친다.
- 상태: 입장 중, 연결됨, 불안정, 재연결, 상대 이탈, 권한 상실, 세션 종료, 연장 제안
- 침묵 개입은 기존 단계 규칙을 유지하고 한 번에 하나만 노출한다.

### S-03 세션 종료 확인

- S-02 위 AlertDialog
- 현재 세션을 끝내는 결과와 상대에게 보이는 상태를 설명한다.
- Primary Danger: `세션 종료`
- Secondary: `계속 대화`
- 네트워크 장애로 이미 종료된 경우 확인 질문이 아닌 결과 안내로 전환한다.

## 7. 평가와 리포트

### R-01 상대 평가 `/session/:sessionId/review`

- 목적: 대화 행동을 평가하고 필요한 경우 신고/차단
- 구조: 상대 별칭/세션 요약 → 정량 문항 → 잘한 행동 → 개선 행동 → 자유 의견
- 문항을 한 묶음씩 보여주고 완료 수를 진행률로 표시한다.
- Primary: `평가 제출`
- 신고/차단은 오버플로 메뉴에 두되 찾기 어렵게 숨기지 않는다.
- 상태: 문항 로딩, 일부 입력, 제출 중, 이미 제출, 세션 자격 없음

### R-02 받은 피드백 `/session/:sessionId/feedback`

- 목적: 상대가 준 피드백을 안전한 문장으로 확인
- 구조: 요약 한 문장 → 잘한 점 → 다음에 해볼 점 → 자유 의견 → 리포트 이동
- Primary: 리포트 준비 시 `AI 리포트 보기`, 준비 중이면 `홈으로`
- 상태: 피드백 있음, 아직 없음, 상대 미제출, 차단/신고 후 제한, 오류

### R-03 리포트 목록 `/reports`

- 목적: 지난 세션과 리포트 상태를 시간순으로 탐색
- 구조: 편집형 페이지 헤더 → 필터/기간 → 강조 리포트 1개 → 목록
- 각 항목: 날짜, 상대 별칭, 세션 유형, 리포트 상태, 핵심 문장
- Primary는 목록 전체에 두지 않고 각 항목의 `리포트 보기`로 둔다.
- 상태: 로딩, 완성 리포트, 생성 중, 생성 실패/재요청, 빈 목록, 페이지 추가 로딩
- 모바일은 카드, 데스크톱은 구분선 기반 목록을 권장한다.

### R-04 세션 리포트 `/session/:sessionId/report`

- 목적: 한 세션의 핵심 학습과 다음 행동을 이해
- 구조: 세션 메타 → 핵심 해석 → 지표 요약 → 축별 상세 → 근거 → 다음 연습 CTA
- 차트는 보조 정보이며 선택 축을 키보드로 탐색할 수 있어야 한다.
- Primary: `다음 연습 시작`
- 상태: 생성 전, 생성 중, 완료, 일부 축 미측정, 생성 실패, 재생성 중
- 생성 중/실패 상태에서 샘플 점수를 표시하지 않는다.

### R-05 성장 대시보드 `/growth`

- 목적: 여러 세션에 걸친 변화와 반복 패턴을 발견
- 구조: 기간/트랙 필터 → 핵심 변화 문장 → 온도 추이 → 강점/개선 키워드 → 배지/누적 기록
- 첫 화면은 숫자 묶음이 아니라 `지난 4주 동안 질문 이어가기 횟수가 늘었어요` 같은 변화 문장을 중심으로 한다.
- 차트에는 데이터 범위, 축 라벨, 데이터 없음 기준을 표시한다.
- 상태: 전체/트랙별, 데이터 충분, 데이터 부족, 빈 기록, 부분 API 실패, 페이지 이동

## 8. 마이와 개인정보

### P-01 마이페이지 `/me`

- 목적: 내 프로필, 참여 기록, 개인정보, 계정 행동의 허브
- 구조: 프로필 헤더 → 참여 기록 → 개인정보/동의 → 계정
- 얼굴상 이미지는 장식이 아니라 현재 설정 프로필로 설명한다.
- 로그아웃과 회원 탈퇴는 일반 수정 항목과 분리한다.
- 상태: 프로필 로딩/없음, 로그아웃, 탈퇴 확인/실패

### P-02 동의 관리 `/me/consent`

- 목적: 현재 동의 상태 확인과 선택 동의 철회
- 각 항목에 목적, 필수 여부, 동의 일시, 철회 영향을 표시한다.
- 철회는 확인 다이얼로그 후 반영하고 되돌릴 수 없는 결과를 설명한다.
- 상태: 로딩, 저장 중, 철회 성공/실패, 필수 동의 변경 불가

### P-03 개인정보 허브 `/me/edit`

- 목적: 얼굴상, 설문, 기본 프로필, 지역 수정 진입점
- 구조: 현재 요약값 + 항목별 `수정` 링크
- 데이터가 없을 때 `미설정`만 두지 않고 설정 행동을 제공한다.
- 상태: 병렬 로딩, 일부 데이터 실패, 미설정

### P-04 기본 프로필 수정 `/me/edit/profile`

- 닉네임과 변경 가능한 기본 정보를 `FormShell`에서 편집한다.
- 성별 등 변경 불가 값은 입력처럼 보이지 않는 설명형 행으로 표시한다.
- Primary: `변경사항 저장`
- 상태: 기존 값, 변경 없음, 검증 오류, 저장 중/완료

### P-05 지역 수정 `/me/edit/region`

- 시·도 선택과 매칭에 쓰이는 범위를 설명한다.
- Primary: `지역 저장`
- 상태: 기존 값, 미선택, 저장 실패

## 9. AI 챗봇

### C-01 페르소나 설정 `/chatbot/persona`

- 목적: 대화 상대와 연습 단계를 설정
- 구조: 추천 페르소나 → 지역 → 연습 단계 → 예상 대화 방식
- Primary: `이 상대와 대화 시작`
- 상태: 옵션 로딩, 추천 중, 기존 세션 있음, 생성 실패

### C-02 챗봇 대화 `/chatbot`, `/chatbot/:chatSessionId`

- 목적: 텍스트로 대화를 연습하고 메시지별 코칭을 선택적으로 확인
- 데스크톱: 대화 8열 + 페르소나/세션 정보 4열
- 모바일: 대화 전체 화면, 정보는 시트
- Composer는 키보드와 safe-area 위에 고정하되 메시지를 가리지 않는다.
- 상태: 세션 없음, 이력 로딩, 메시지 전송 중, 스트리밍 응답, 응답 중단, 재시도, 오프라인, 종료
- AI/사용자 메시지는 정렬, 이름, 표면을 함께 달리한다.

### C-03 챗봇 리포트 `/chatbot/:chatSessionId/report`

- 목적: 텍스트 연습의 대화량, 잘한 점, 다음 행동 확인
- 구조: 대화 요약 → 핵심 문장 → 강점 → 개선 → 추천 표현 → 다시 연습
- Primary: `같은 상대와 다시 연습`
- 상태: 생성 중, 완료, 생성 실패, 대화량 부족

## 10. 알림과 오버레이

### O-01 알림 패널

- 데스크톱: 우측 상단 popover, 모바일: full-height sheet
- 항목: 유형 아이콘, 제목, 설명, 시각, 읽음 상태
- 행동: 항목 이동, 모두 읽음, 추가 로드
- 상태: 로딩, 빈 알림, SSE 끊김, 읽음 처리 실패

### O-02 신고/차단 시트

- 신고 사유, 추가 설명, 차단 선택, 처리 결과를 단계적으로 제공한다.
- 신고와 차단의 차이, 세션 종료 여부를 제출 전에 설명한다.
- 상태: 입력, 제출 중, 완료, 실패, 중복 신고

## 11. 범위 밖 또는 후속 명세

- `/admin/*`: 기능성 중심 별도 관리자 디자인 스프린트
- `/gallery`: 새 디자인 시스템 리빙 스타일가이드
- `/demo`, `/livekit-demo`: 내부 QA 도구, 사용자 내비게이션에서 숨김
- AI 화상 트랙: 실제 출시가 확정될 때 별도 S-MEDIA 변형 작성

## 12. 화면 완료 정의

각 화면은 다음 항목이 모두 충족돼야 완료다.

- 기본 모바일/데스크톱 와이어프레임과 필요한 상태 변형이 승인됨
- 실제 API 필드와 노출 정책이 대응됨
- Primary CTA와 다음 경로가 하나로 정리됨
- Loading/Empty/Error/Offline 상태가 구현됨
- 320~1440px 반응형 검수 완료
- 키보드, 포커스, 터치 타깃, 대비, reduced-motion 검수 완료
- 영상/이미지 실패 시 폴백 확인
- 기존 기능 회귀 체크리스트 통과
