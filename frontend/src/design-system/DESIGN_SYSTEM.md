## 1. 디자인 원칙

이 서비스는 소개팅 앱이 아니라 **연습 도구**다. 사용자는 "소개팅에서 매번 실패하지만 이유를 모르는" 상태로,
**이미 긴장한 채** 들어온다. 아래 6개는 취향이 아니라 판단 기준이다. 새 화면이 이 중 하나라도 어기면 그 화면이 틀린 것이다.

| # | 원칙 | 의미 | 근거 |
|---|---|---|---|
| 1 | **연습이지 심사가 아니다** | 외모·매력 점수를 어떤 형태로도 표시하지 않는다. 점수는 오직 *대화 행동*에만 붙고, 항상 근거 문장과 함께 나온다. 숫자 단독 노출 금지 | §4.3 · §5.1 · §16.2 |
| 2 | **코칭은 나에게만, 조용히** | 모든 코칭은 본인 화면 전용. 상대 영상을 가리지 않고, 한 번에 하나만, 스스로 사라진다. 코칭 UI는 절대 전체 화면을 덮지 않는다 | §10 |
| 3 | **단정하지 않는다** | 표정→감정 추정은 유사과학 논란 리스크가 있다. AI 추정 정보에는 `.bt-hedge` 배지와 "~해 보일 수 있어요" 화법이 **필수** | §10.1 · §14 |
| 4 | **개입은 늦게, 물러남은 빠르게** | 10초 이내 침묵엔 개입하지 않는다. 적당한 침묵은 대화의 일부다. 등장 560ms, 퇴장 160ms | §10.4 · §11.1 |
| 5 | **최소 공개** | 상대에게 보이는 건 닉네임·연령대·키·얼굴상뿐. 실명·연락처·정확한 지역·내부 점수는 어떤 화면에도 렌더링하지 않는다 | §4.1 · §22 |
| 6 | **피어남의 미학** | 여백 우선, 저채도, 큰 라운드, 낮은 알파의 넓은 그림자. 경고색은 진짜 안전 이슈에만. 긴장한 사용자를 더 긴장시키지 않는 것이 목표 | 컨셉아트 |

## 2. 토큰 아키텍처

3계층이며, **컴포넌트는 semantic 레이어만 참조한다.**

```
primitive          semantic                컴포넌트
--bt-blue-500  →   --bt-color-brand    →   .bt-ring (conic-gradient)
--bt-blue-600  →   --bt-color-action   →   .bt-btn--primary
```

> **규칙:** 컴포넌트 CSS에서 `--bt-blue-500` 같은 primitive를 직접 쓰면 **다크모드가 깨진다.**
> 다크 전환은 semantic 레이어에서만 일어나기 때문이다. 리뷰에서 이것만은 반드시 잡아야 한다.

## 3. 색

### 3.1 Bloom Blue — 그리고 브랜드/액션을 나눈 이유

컨셉아트의 버튼·FAB·점수 링에서 샘플링한 실제 브랜드 블루는 **`#5B8BEF`**다. 그런데 이 색에 흰 글자를 얹으면
대비가 **3.29:1**로, WCAG AA 본문 기준(4.5:1)에 **미달한다.** 컨셉의 "매칭 시작하기" 버튼이 정확히 이 상태다.

컨셉의 얼굴을 버릴 수도, 접근성을 버릴 수도 없으므로 **역할을 쪼갰다.**

| 토큰 | 값 | 대비(흰 글자) | 용도 |
|---|---|---|---|
| `--bt-color-brand` | `#5B8BEF` ★원본 | 3.29:1 | **글자가 없는 곳**: 점수 링, 아이콘, 그래프, 장식 (비텍스트 UI 3:1 통과) |
| `--bt-color-action` | `#336EEB` | **4.59:1 ✓** | **글자가 올라가는 곳**: fill 버튼, FAB |
| `--bt-color-text-link` | `#1553D6` | **6.48:1 ✓** | 링크·강조 텍스트 |

육안으로 `#5B8BEF`와 `#336EEB`는 거의 구분되지 않지만, 대비는 3.29 → 4.59로 넘어간다. **컨셉의 인상은 유지되고 규정은 통과한다.**

전체 램프(hue 220.5 / sat 82% 고정):

| | 50 | 100 | 200 | 300 | 400 | 500★ | 600✓ | 700 | 800 | 900 |
|---|---|---|---|---|---|---|---|---|---|---|
| hex | `#EFF3FD` | `#DEE8FC` | `#BED1F9` | `#99B7F5` | `#7DA3F2` | `#5B8BEF` | `#336EEB` | `#1553D6` | `#1041A7` | `#0C2F79` |

### 3.2 Mist — 뉴트럴

컨셉의 배경은 **순백이 아니라** 아주 옅은 웜그레이 `#F8F8FA`다. 그래서 흰색(`#FFFFFF`) 카드가
**그림자 없이도** 배경에서 떠 보인다. 이 관계가 컨셉 공기감의 핵심이므로 깨지 말 것.

`0 · 25 · 50 · 100 · 200 · 300 · 400 · 500 · 600 · 700 · 800 · 900 · 950` + `--bt-ink: #17181F`(헤드라인 샘플값)

- 본문 = `--bt-ink` (17.05:1)
- 보조 텍스트 = `--bt-mist-600` `#62656E` (5.82:1 ✓)
- `--bt-mist-500` `#8A8D98`은 **3.31:1로 본문에 쓸 수 없다.** placeholder·disabled 전용.

### 3.3 시맨틱 — 그리고 하트와 신고가 같은 빨강인 문제

| 계열 | marker(비텍스트) | 텍스트(AA) | 용도 |
|---|---|---|---|
| **Leaf** 초록 | `#57C97E` | `#208844` (4.50:1) | 성공·강점·접속중 dot |
| **Pollen** 앰버 | `#F0A93C` | `#A6690C` (4.52:1) | 주의·성장 포인트("실패"가 아니라 "다음에 해볼 것") |
| **Rose** 빨강 | `#E4404F` ★원본 | `#CE1D2D` (5.47:1) | 통화 종료·신고·**하트** |

> ⚠️ **컨셉아트에서 하트(호감)와 통화 종료가 같은 빨강이다.** 소개팅 맥락에서 "빨강 = 호감"과
> "빨강 = 위험"이 충돌한다. 색을 바꾸는 대신 **색만으로 구분하지 않는 규칙**으로 해결한다 —
> 파괴적 액션(`.bt-btn--danger`)에는 **반드시 아이콘 + 라벨**을 함께 붙인다. 아이콘만 있는 빨강 원형은
> 통화 종료 하나뿐이며, 그 자리는 학습된 관습이라 예외로 둔다.

또한 **마이크·카메라 끔은 빨강이 아니라 중립 회색**(`.bt-icon-btn--off`)이다. 되돌릴 수 있는 상태에
빨강을 쓰면 종료 버튼과 혼동된다.

## 4. 타이포그래피

**Pretendard Variable** 단일 서체. 한글·영문·숫자를 한 서체로 처리해 혼용 시 베이스라인이 흔들리지 않는다.
스케일은 팀이 이미 [`디자인_연결_다크.png`](../디자인시안/디자인_연결_다크.png) 시안에서 쓰던
`32 / 24 / 20 / 16 / 14 / 12` 체계를 **그대로 승계**하고 Display(40)·Body-lg(17)만 추가했다.

| 토큰 | 크기/행간/굵기 | 자간 | 용도 |
|---|---|---|---|
| `display` | 40 / 1.2 / 700 | -0.035em | 히어로 |
| `h1` | 32 / 1.3 / 700 | -0.02em | 페이지 타이틀 |
| `h2` | 24 / 1.35 / 600 | -0.02em | 섹션 |
| `h3` | 20 / 1.4 / 600 | -0.02em | 카드 타이틀 |
| `body-lg` | 17 / 1.6 / 400 | 0 | 리드문 |
| `body` | 16 / 1.6 / 400 | 0 | 본문 |
| `body-sm` | 14 / 1.6 / 400 | 0 | 보조 |
| `caption` | 12 / 1.5 / 400 | 0 | 메타·시각 |
| `micro` | 11 / 1.45 | 0 | 네비 라벨·배지 |

- **한글 제목엔 자간 `-0.02em` 필수.** 안 하면 뭉쳐 보인다.
- **본문 행간 1.6 유지.** 한글은 1.5 미만이면 답답하다.
- **본문에 700 금지.** 한글은 600에서 이미 충분히 강하다.
- 점수·타이머·시각엔 `.bt-numeric`(tabular-nums) — 숫자가 바뀔 때 흔들리지 않는다.
- `--bt-font-script`(Caveat)는 **"Practice, Connect, Bloom" 태그라인 전용.** UI 텍스트 사용 금지.

## 5. 여백 · 라운드 · 그림자 · 모션

**Spacing** — 4px 베이스 8pt 그리드: `4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80`

**Radius** — `xs 8`(배지) `sm 12`(아바타) `md 16`(인풋) `lg 20`(내부 카드) `xl 28`(메인 카드) `2xl 32`(모달) `pill`(버튼·칩·네비)

> **중첩 규칙: 안쪽 라운드 = 바깥 라운드 − 패딩.** 28px 카드에 24px 패딩이면 내부 카드는 20px(lg).
> 컨셉아트가 정확히 이 관계다.

**Elevation** — 컨셉의 그림자는 **진하지 않고 넓다.** 알파 **0.04–0.10** 범위를 벗어나면 컨셉의 공기감이 사라진다.
다크모드에선 그림자가 보이지 않으므로 대비는 **표면 밝기**로 만든다(토큰에 반영됨).

**Glass** — `rgba(255,255,255,.72)` + `blur(20px) saturate(1.4)` + 흰 1px 스트로크. 네비·코치 카드·통화 컨트롤 바에 사용.

**Motion** — 원칙 4가 토큰으로 내려온 것:

| 토큰 | 값 | 용도 |
|---|---|---|
| `instant` | 100ms | 버튼 눌림(scale .97) |
| `fast` | 160ms | hover, **코칭 퇴장** |
| `base` | 220ms | 토글·상태 전환 |
| `slow` | 320ms | 모달·시트 |
| `bloom` | 560ms | **코치 카드 등장**, 점수 링 채우기 |
| `ease-bloom` | `cubic-bezier(.34,1.4,.64,1)` | 완만한 오버슛 |

`prefers-reduced-motion`이 켜지면 모든 duration이 1ms로, `ease-bloom`은 standard로 **토큰 레벨에서 자동 대체**된다.

### 6.1 React 래퍼 사용 규칙

`.bt-*` 클래스를 직접 쓰지 말고 `@/components` 배럴의 래퍼를 쓴다. 클래스 조합에 접근성 계약이 묶여 있다.

| 하지 말 것 | 대신 | 이유 |
|---|---|---|
| `<div className="bt-card bt-card--interactive" onClick>` | `<CardButton>` / `<CardLink as={Link}>` | div 는 포커스·Enter/Space 가 없다 |
| `<ListRow>` 안에 버튼 중첩 | `<ListRow>`(비상호작용) + 내부 버튼 | 버튼 중첩은 유효하지 않은 인터랙션 |
| `<Field label><input/></Field>` | `<Field label><Input/></Field>` | `Input` 만 컨텍스트에서 id/aria 를 받아간다 |
| `Segmented` 를 탭으로 사용 | 탭이 필요하면 별도 Tabs 컴포넌트 | `role="tab"` 은 tabpanel·방향키·roving tabIndex 가 전제 |
| `Modal` 에 이름 없이 사용 | `title` 또는 `aria-label` (타입으로 강제) | 이름 없는 다이얼로그는 탐색 불가 |
| `useTheme()` 를 Provider 밖에서 | 루트를 `<ThemeProvider>` 로 감싼다 | 상태가 분기되면 토글끼리 어긋난다 |

**레이더 차트**(`REPORT-01`)는 Chart.js로 구현하되 색은 토큰을 주입한다:
AI 분석 = `--bt-color-brand`(`#5B8BEF`), 상대 평가 = `--bt-color-success-marker`(`#57C97E`).
두 계열은 색상환에서 충분히 떨어져 있고, 색각 이상에서도 명도차(3.29 vs 2.09 상대휘도)로 구분된다.

## 7. 핵심 패턴

### 7.1 침묵 단계별 개입 — 이 시스템의 서명 인터랙션

기능이 아니라 **태도**다. "적당한 침묵은 대화의 일부"라는 기획 철학이 UI 강도로 번역된 것이고,
각 단계는 앞 단계보다 **딱 한 칸만** 세진다.

| 침묵 | UI | 컴포넌트 |
|---:|---|---|
| 0–10초 | **개입 없음** — 아무것도 그리지 않는다. 이 단계를 구현하지 않는 게 아니라, *침묵을 견디는 것*이 이 단계의 구현이다 | — |
| 15–20초 | 화면 가장자리에 작은 주제 버튼, opacity .9. 무시해도 부담 없는 크기 | `.bt-topic-btn` |
| 30초 | 선택형 질문 카드(범용 랜덤 질문 3개). 여전히 상대 영상을 가리지 않는다 | `.bt-question-card` |
| 45초+ | AI 코치가 맥락 기반 구체 질문 3개. **최대 강도이며 그 이상은 없다** | `.bt-coach` + `.bt-question-card` |

### 7.2 목적별 동의 (`AUTH-03`)

전체 동의 체크박스 하나로 묶지 **않는다.** 각 항목은 개별 토글이고, **선택 동의를 모두 꺼도 기본 화상 연습은 동작해야 한다.**
처리 기준(보관·삭제)을 각 행에 그대로 노출한다. → `.bt-consent`

### 7.3 세션 화면은 항상 다크

화상 세션(§9)·상황형 대기방(§8)은 **상대의 얼굴이 주인공**이다. 밝은 UI는 영상과 밝기 경쟁을 하므로
이 화면들은 OS 설정과 무관하게 `data-theme="dark"`로 **고정**한다.

> ⚠️ **스코프 테마 필수 규칙:** `data-theme`을 루트가 아닌 요소에 걸면 변수는 서브트리에서 바뀌지만
> `color`는 상위에서 이미 계산된 값이 그대로 상속된다 → **다크 배경 위 다크 텍스트(대비 1.1:1)**.
> `tokens.css` 하단의 `[data-theme] { color: var(--bt-color-text); }`가 이걸 막는다. **지우지 말 것.**
> (실제로 구현 중 발생했고, 이 규칙으로 1.1:1 → 14.5:1로 수정됨)

### 7.4 피드백 화법 — 문장도 컴포넌트다

이 서비스에서 **문장은 컴포넌트만큼 중요한 인터페이스**다. 사용자는 이미 긴장한 상태다.

| ✅ 이렇게 | ❌ 이렇게 말고 |
|---|---|
| "상대가 취미를 말한 뒤 본인 이야기로 전환한 구간이 **3회** 있었어요" — 사실 + 횟수 | "대화 능력 62점 / 하위 30%" — 등수·심사 프레임 |
| "관심 있게 듣는 모습으로 **보일 수 있어요**" — 추정은 추정으로 | "상대는 지루해했습니다" — 감정 단정 |
| "질문을 조금 더 다양하게 시도해보세요" — 다음 행동 제안 | "당신은 자기 얘기만 하는 타입입니다" — 인격 규정 |
| "앞으로 어떤 삶을 살고 싶은지 궁금해요" — 대체 문장 제시(§16.5) | "매력도 낮음" — 외모·매력 평가는 **어떤 형태로도 금지** |

## 8. 접근성 (WCAG 2.1 AA)

**컨셉아트를 그대로 코드로 옮기면 대비 미달이 발생한다.** 아래가 실측값이며 토큰은 이미 이를 반영해 분리돼 있다.

| 조합 | 대비 | AA 본문(4.5:1) | 결론 |
|---|---|---|---|
| `#5B8BEF` + 흰 글자 *(컨셉 원본 버튼)* | 3.29:1 | ✗ | 비텍스트 UI만 (3:1 통과) |
| `#336EEB` + 흰 글자 *(action)* | 4.59:1 | ✓ | 모든 fill 버튼의 기본값 |
| `#1553D6` on `#FFF` *(link)* | 6.48:1 | ✓ | 링크·강조 |
| `#17181F` on `#F8F8FA` *(ink)* | 17.05:1 | ✓ | 본문 |
| `#62656E` on `#FFF` *(mist-600)* | 5.82:1 | ✓ | 보조 텍스트 |
| `#8A8D98` on `#FFF` *(mist-500)* | 3.31:1 | ✗ | placeholder·disabled 한정 |
| `#E4404F` + 흰 글자 *(컨셉 통화종료)* | 4.08:1 | ✗ | 아이콘 버튼만. 라벨 있으면 600 |
| `#208844` on `#FFF` *(leaf-700)* | 4.50:1 | ✓ | 성공 텍스트 |

그 외 강제 규칙:

- **터치 타깃 44×44 최소**(`--bt-tap-min`). 세션 통화 컨트롤은 급할 때 눌러야 하므로 56px.
- **포커스 링을 지우지 않는다.** 모든 인터랙티브 요소가 동일한 2px 링 + 2px offset을 공유한다.
  이 코드베이스에서 `outline: none`은 **버그**다.
- **색만으로 알리지 않는다.** (§3.3의 하트/신고 충돌)
- **동작 축소 존중.** `prefers-reduced-motion`에서 오버슛·펄스·shimmer가 모두 정지한다.
- 세션 중 코칭 토스트는 `aria-live="polite"`로 알린다. `assertive`는 금지 — 대화를 방해한다.

## 9. 확장 규칙

새 컴포넌트를 추가할 때:

1. **기존 컴포넌트로 안 되는지 먼저 확인한다.** 변형(modifier)으로 되면 새로 만들지 않는다.
2. **semantic 토큰만 참조한다.** primitive 직접 참조는 리뷰에서 반려.
3. **상태를 전부 정의한다.** default / hover / active / focus-visible / disabled / loading / error.
4. **라이트·다크 양쪽에서 확인한다.** `preview.html` 우상단 토글로 즉시 검증 가능.
5. **원칙 6개에 위배되지 않는지 확인한다.** 특히 원칙 1(점수)과 3(단정).
6. `preview.html`에 예시를 추가한다. **문서화되지 않은 컴포넌트는 존재하지 않는 것으로 간주한다.**

## 부록: 색 추출 방법

컨셉아트 PNG를 zlib 디코딩해 좌표별 픽셀을 직접 샘플링했다(안티에일리어싱 영향을 줄이려 영역별
최빈값·최고채도·최저휘도를 함께 측정). 주요 추출값:

| 대상 | 샘플값 | 토큰 |
|---|---|---|
| "매칭 시작하기" 버튼 | `#5E8EEE` | → `--bt-blue-500` `#5B8BEF` |
| 페이지 배경 | `#F8F8F8` | → `--bt-mist-50` `#F8F8FA` |
| 글래스 카드 내부 | `#FCFCFC` | → `--bt-mist-25` |
| 헤드라인 | `#131623`~`#1E1E26` | → `--bt-ink` `#17181F` |
| 보조 텍스트 | `#606269` | → `--bt-mist-600` `#62656E` |
| 통화 종료 / 하트 | `#E43E50` / `#E94553` | → `--bt-rose-500` `#E4404F` |
| 접속중 dot | `#8ACF67` | → `--bt-leaf-500` (계열 통일 위해 hue 140으로 정규화) |
| 하단 네비 활성 | `#4984ED` | → `--bt-color-action` |
| 점수 링 | `#5289F0` | → `--bt-color-brand` |

각 단계의 대비를 예측 가능하게 만들기 위해서다.
